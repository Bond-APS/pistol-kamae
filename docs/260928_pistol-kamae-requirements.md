# Pistol Kamae 要件定義（案）

- 作成日：2026-09-28
- 状態：壁打ち結果の整理。最終確定はつよし。
- 対象：AP（エアピストル）の射撃姿勢解析 Web アプリ

---

## 1. 背景と目的

APS 仲間の AP 選手から、以前試作した MediaPipe（Google 製の姿勢推定ライブラリ）を使った姿勢解析アプリを完成させてほしいとの要望。

目的：ベストに近い射撃ができたときの姿勢を「基準（リファレンス）」として保存し、不調時の動画と重ね合わせ・角度比較を行うことで、感覚では気づけない姿勢の違いを見つけるきっかけを与える。

## 2. やらないこと（非目標）

- 複数カメラ・SCATT・CSV の同期記録（以前の試作の範囲）。将来も v1 では扱わない
- 側面カメラ。前後方向の姿勢変化（腰の反り、頭の前後位置）は正面カメラでは検出できず、それを了承済み。画面への注記は不要
- 頭の傾き（両目線の角度）。顔がターゲット方向を向くため正面カメラでは両目が写らない
- 手首の返り（銃の向き）。銃は検出対象外
- ブラウザ内での動画形式変換（将来のバージョンアップ候補）
- 動画本体の保存（容量・プライバシーのため）
- サーバへの送信（一切なし）

## 3. 利用者・動作環境

- 利用者：AP 射手。複数人が同じ端末を使う可能性あり（射手名で管理）
- 端末：Mac、Windows、iPad、スマートフォン（iPhone／Android）。ブラウザで動作する Web アプリ（PWA：ホーム画面に追加してアプリのように使える方式）
- スマートフォンでも一通りの操作が完結する UI・UX とする
- 処理・保存はすべて端末内で完結（動画を外部に出さない）
- 公開：GitHub Pages で一般公開、MIT ライセンス、無保証。問い合わせ対応は可能な範囲のみ

## 4. 入力動画

- 撮影：iPhone または Android、三脚固定、正面（射手のへそ側）から全身。縦長推奨
- 1 本の動画に 1 発のみを前提とする
- 形式：ブラウザが再生できる形式なら縦横・fps を問わず受け付ける。再生できない場合（例：iPhone 標準の HEVC 形式を Windows の Chrome で開く）は、案内を表示する
  - 案内例：iPhone は「設定 → カメラ → フォーマット → 互換性優先」で撮影
  - 初回画面に「読める形式の一覧」を明示
- 読込前に「動画は事前に短くトリミングすることを推奨」の注記を初回画面と読込ボタン付近に表示（全長に姿勢推定をかけるため、長い動画は処理時間が延びる。1 分程度の待ちは許容）

## 5. 機能一覧（v1）

1. 動画読込（ファイル選択のみ。ブラウザ内撮影は行わない）
2. 姿勢推定：動画全長に実行、進捗バーと中断ボタンを表示。生の座標を保存し、表示用の平滑化（移動平均）は後段で任意に適用
3. マーク付け：撃発フレーム（必須）＋任意ラベルのマーク（振り上げ開始など、任意個。同じ名前は 1 動画に 1 つまで）。フレーム送り・戻しは時刻ベースで実装（±1 フレーム程度の誤差は許容）
4. 角度計測：撃発フレームおよび全フレームの角度（第 6 章）
5. ライブラリ：処理済み動画を一覧。日付・射手名・点数・メモ・お気に入り・サムネイル。射手名でフィルタ。お気に入りは複数指定可
6. 比較：基準（お気に入りから 1 つ選択）と任意の動画を重ね描き。差分表と角度時系列グラフ
7. 静止ノイズ測定モード（第 8 章）
8. 書き出し・読込：JSON（全データ）、CSV（角度時系列）、PNG（重ね描き画像）。JSON は読込可能で端末間共有に使う
9. 利き手設定（右／左）。内部は「銃側／非銃側」で扱い、表示の意味が同じになるよう左利きは反転
10. 保存はブラウザ内データベース（IndexedDB）。初回画面で「ホーム画面に追加」と「JSON 書き出し」を促す（iOS Safari は 7 日間未使用のサイトの保存データを消すことがあり、ホーム画面追加で回避できる）

## 6. 計測定義

### 6.1 使用する点（MediaPipe の 33 点から）

| 名称 | 定義 |
|---|---|
| 銃側手首 | 利き手側の wrist |
| 両肩 | left/right shoulder |
| 肩中心 | 両肩の中点 |
| 両腰 | left/right hip（大転子付近に出る点。実際の骨盤中心より外側・下方に出ることを承知のうえで使用） |
| 腰中心 | 両腰の中点 |
| 顔 | 銃側の耳（右射手をへそ側から撮ると、頭はターゲット方向＝画面左を向くため、カメラに見えるのは銃側の耳）。visibility が低ければ鼻に代替 |
| 両足首 | left/right ankle |

visibility（MediaPipe が出す「その点がどれだけ見えているか」の値）が閾値未満の点は計測から外し、グレー表示、角度は「—」とする。

### 6.2 角度・距離の一覧

| 記号 | 名称 | 定義 | 基準 |
|---|---|---|---|
| (a) | 肩線の傾き | 両肩を結ぶ線 | 水平 |
| (b) | 腰線の傾き | 両腰を結ぶ線 | 水平 |
| (c) | 体軸の傾き | 腰中心 → 肩中心 | 鉛直 |
| (d) | 首の傾き | 肩中心 → 顔 | 鉛直 |
| (f) | 腕の挙上角 | 銃側肩 → 銃側手首 | 水平 |
| (g) | 腕と肩線のなす角 | (f) の線と (a) の線 | 身体基準 |
| (h) | 腰中心の横ずれ | 両足首中点に対する腰中心の水平オフセット | 体幹長で正規化した比率 |
| (i) | スタンス幅 | 両足首間距離 ÷ 体幹長 | 比率 |
| (j) | 手首と顔の水平距離 | 銃側手首と顔の x 座標差 ÷ 体幹長 | 比率 |

(e) 頭の傾きは計測不能のため除外。

### 6.3 基準と符号

- 基準は「カメラの水平・鉛直」と「身体基準」の両方を持つ
- 水平校正（任意）：動画上で床線や射座の縁など既知の水平線を 1 本引き、カメラの傾きを補正する。日を跨いだ三脚の傾き差を吸収するため
- 符号：銃側へ傾く・上がる＝正。左利きは内部で反転

### 6.4 正規化（重ね描き用）

- 既定：腰中心で平行移動、体幹長（腰中心 → 肩中心）でスケール
- トグルで生の画素座標のまま重ねることも可能（立ち位置のずれ自体を見たいとき）

## 7. 比較の定義

- (a) 撃発フレームの静止姿勢を重ねる
- (b) 撃発前後の一連動作を、同期点で揃えて角度時系列を 2 本重ねる。時間伸縮はしない
- 同期点：撃発マークを既定とし、任意マーク（振り上げ開始など）を選ぶこともできる
- 切り出し幅（撃発 −N 秒〜＋M 秒）は設定可
- 差分表示：基準値・現在値・差分の 3 列表。差分がノイズ幅（第 8 章）を超えた項目だけ色を付ける。閾値はユーザーが上書き可
- 重ね描き：基準は半透明の別色。横並び表示もトグルで可

## 8. 静止ノイズ測定

- 三脚固定・射手が静止した動画を読み込み、各角度のノイズ幅（標準偏差）を表示するモード
- 得られた値を差分表示の色分け閾値の既定値に流用
- 開発上の意味：MediaPipe の点は静止していても数ピクセル揺れる。1080p の全身像では肩線の角度で ±1° 前後のノイズが見込まれる（推定、要実測）。友人が見たい差がこれより小さければ、複数フレーム平均や高解像度化を先に検討する

## 9. データ仕様

- 保存単位：処理済み動画 1 件
- 保存項目：ランドマーク時系列（33 点 × x, y, visibility × フレーム）、fps・解像度、マーク（撃発、任意ラベル）、水平校正の線、角度時系列、メタ情報（日付、射手名、点数、メモ、お気に入り、利き手）、使用した姿勢推定モデルの名前（例：`mediapipe-full-video`）、静止画数枚（撃発フレームなど、重ね描き用）
- 動画本体は保存しない。必要なら再度ファイル選択で紐付け
- JSON：上記すべて。読込可
- CSV：角度時系列（列名は第 6.2 章の名称）
- PNG：重ね描き画像

## 10. 画面構成と操作フロー

1. 初回画面：形式の案内、トリミング推奨、ホーム画面追加・JSON 書き出しの案内
2. 読込画面：ファイル選択 → 姿勢推定（進捗・中断）
3. マーク画面：再生・時刻ベースのフレーム送り、撃発マーク、任意マーク、水平校正
4. ライブラリ画面：一覧、射手名フィルタ、お気に入り、メタ情報編集
5. 比較画面：重ね描き／横並び、差分表、時系列グラフ、同期点・正規化・基準の切替
6. 設定画面：利き手、切り出し幅、平滑化、閾値
7. 静止ノイズ測定画面

## 11. 技術構成

| 部品 | 採用 | 説明 |
|---|---|---|
| 画面の組み立て | React | 画面部品を組み立てる仕組み |
| プログラム言語 | TypeScript | JavaScript に型を足した言語。誤りを実行前に見つけられる |
| まとめ道具 | Vite | プログラムをブラウザで動く形に束ねる道具。出力をそのまま公開 |
| 姿勢推定 | MediaPipe Tasks Vision（ブラウザ版） | 関節 33 点を検出。モデルは full・動画モードに固定（利用者には選ばせない） |
| グラフ | Chart.js | 角度時系列の折れ線 |
| 保存 | Dexie | ブラウザ内データベース IndexedDB の扱いを簡単にする部品 |

- すべて無料・オープンソース。MediaPipe は Apache 2.0 で、MIT のアプリに組み込んで問題なし
- 姿勢推定と角度計算は画面から切り離した独立部品（ライブラリ）として作り、将来別アプリに組み込めるようにする
- 姿勢推定の出力はモデルごとに異なる（MediaPipe 33 点、MoveNet・RTMPose・ViTPose は COCO 形式 17 点、Sapiens 2 は 308 点）。engine の内側に「共通ランドマーク形式」（6.1 章の点：鼻・両耳・両肩・両腰・両手首・両足首、各 x, y, visibility）を定義し、どのモデルの出力もそこへ変換してから角度計算に回す。角度計算・比較画面はモデルに依存しない
- 姿勢推定バックエンドは差し替え可能にする。ブラウザ内は MediaPipe を使う。段階①で MoveNet Thunder（Google、TensorFlow.js）、MediaPipe lite／heavy と同じ動画で静止ノイズを比較済み。すべて合格ライン内だったため、MediaPipe full に一本化した
- 文言は最初から分離しておき、英語化を容易にする（v1 は日本語のみ）

## 12. 開発順序と検収基準

| 段階 | 内容 | 合格ライン |
|---|---|---|
| ① | 動画読込 → 姿勢推定 → 骨格重ね描き → 静止ノイズ測定 | iPhone の Safari で、処理時間が動画の長さの 6 倍以内。静止ノイズは肩線・体軸の SD（標準偏差）が 1° 以内 |
| ② | マーク付け → 撃発フレームの角度表 | — |
| ③ | ライブラリ、射手名、お気に入り | — |
| ④ | 2 動画の重ね描き＋差分表、正規化トグル、水平校正 | 同一射手の別日動画を正規化して重ねたとき骨格がおおむね一致する |
| ⑤ | 角度時系列グラフ＋同期点選択 | — |
| ⑥ | JSON／CSV／PNG 書き出しと JSON 読込 | — |
| ⑦ | PWA 化、文言分離 | — |
| ⑧（条件付き） | Mac 用 Python 変換ツール（高精度モード）。動画を入れると共通ランドマーク形式の JSON を出し、Web アプリの JSON 読込で取り込む。まず RTMPose、Apple Silicon 機に更新後 Sapiens 2／ViTPose を追加検討 | ①のノイズ幅が合格ラインに届かない場合にのみ着手 |

- ①で速度が出なければ、モデル・解像度の方針を見直す
- 友人の動画でノイズが合格ラインに届かなければ⑧へ進む。この場合、高精度処理はつよしの Mac で行い JSON を渡す運用を基本とし、その部分は端末内完結の例外とする（友人の動画を預かる前提）
- まず自分の動画で作り込み、ある程度できてから友人に触ってもらう
- 検証動画：友人から最低 3 本（好調時 1 本、不調時 2 本）を入手。可能なら Android 撮影のものも
- 期限なし

## 15. 未決事項（既定値の提案）

| 項目 | 提案 |
|---|---|
| 切り出し幅の既定値 | 撃発 −6 秒〜＋1 秒 |
| visibility の閾値 | 0.5 |
| 表示用平滑化の既定 | なし（移動平均 3〜5 フレームを選択可） |
| 静止ノイズ測定の推奨動画長 | 10 秒以上 |
| 差分の色分け | ノイズ幅の 1 倍で黄、2 倍で赤 |
