# Pistol Kamae 要件定義（案）

- 作成日：2026-09-28
- 状態：壁打ち結果の整理。最終確定はつよし。
- 対象：AP（エアピストル）の射撃姿勢解析 Web アプリ

---

## 1. 背景と目的

APS 仲間の AP 選手から、以前試作した MediaPipe（Google 製の姿勢推定ライブラリ）を使った姿勢解析アプリを完成させてほしいとの要望。

目的：ベストに近い射撃ができたときの姿勢を「基準（リファレンス）」として保存し、不調時の動画と重ね合わせ・角度比較を行うことで、感覚では気づけない姿勢の違いを見つけるきっかけを与える。

## 2. やらないこと（非目標）

- 複数カメラ・SCATT・CSV の同期記録（以前の試作の範囲）。将来も v1 では扱わない
- 側面カメラ。前後方向の姿勢変化（腰の反り、頭の前後位置）は正面カメラでは検出できず、それを了承済み。画面への注記は不要
- 頭の傾き（両目線の角度）。顔がターゲット方向を向くため正面カメラでは両目が写らない
- 手首の返り（銃の向き）。銃は検出対象外
- ブラウザ内での動画形式変換（将来のバージョンアップ候補）
- サーバへの送信（一切なし）

## 3. 利用者・動作環境

- 利用者：AP 射手。複数人が同じ端末を使う可能性あり（射手名で管理）
- 端末：Mac、Windows、iPad、スマートフォン（iPhone／Android）。ブラウザで動作する Web アプリ（PWA：ホーム画面に追加してアプリのように使える方式）
- スマートフォンでも一通りの操作が完結する UI・UX とする
- 処理・保存はすべて端末内で完結（動画を外部に出さない）
- 公開：GitHub Pages で一般公開、MIT ライセンス、無保証。問い合わせ対応は可能な範囲のみ

## 4. 入力動画

- 撮影：iPhone または Android、三脚固定、正面（射手のへそ側）から全身。縦長推奨
- 1 本の動画に 1 発のみを前提とする
- 形式：ブラウザが再生できる形式なら縦横・fps を問わず受け付ける。再生できない場合（例：iPhone 標準の HEVC 形式を Windows の Chrome で開く）は、案内を表示する
  - 案内例：iPhone は「設定 → カメラ → フォーマット → 互換性優先」で撮影
  - 初回画面に「読める形式の一覧」を明示
- 読込前に「動画は事前に短くトリミングすることを推奨」の注記を初回画面と読込ボタン付近に表示（全長に姿勢推定をかけるため、長い動画は処理時間が延びる。1 分程度の待ちは許容）

## 5. 機能一覧（v1）

1. 動画読込（ファイル選択のみ。ブラウザ内撮影は行わない）
2. 姿勢推定：動画全長に実行、進捗バーと中断ボタンを表示。生の座標を保存し、表示用の平滑化（移動平均）は後段で任意に適用
3. 切り抜き（2026-10-03 追加）：前後の余計な部分を外す範囲（開始・終了の時刻）を決める。ファイルは丸ごと保存し、範囲だけを記録に持つ「範囲の記録」方式（ブラウザ内で動画を切って作り直す再エンコードは行わない。端末の保存容量は減らない）。以後の画面はすべて範囲の中だけを動画として扱う。範囲はライブラリと比較画面からあとで直せる
4. 撃発ポイント（必須、1 動画に 1 つ）：切り抜いた範囲の中で、発射の瞬間のコマを指定する。付けるまで保存できない。動画に音声があれば、音の大きさのグラフをバーの上に出し、音が最も大きい瞬間に自動で当たりを付ける（利用者は、修正が必要なときだけ指定し直して「撃発ポイントを確定」を押す）。任意ラベルのマークは画面から外した（保存形式には残す）。フレーム送り・戻しは時刻ベースで実装（±1 フレーム程度の誤差は許容）
5. 角度計測：撃発フレームおよび全フレームの角度（第 6 章）
6. ライブラリ：保存した動画を一覧。タイトル（初期値は撮影日時、自由に変更可）・射手名・切り抜いた長さ・メモ（100 字まで）・お気に入り・サムネイル。射手名でフィルタ、お気に入りのみのフィルタ。お気に入りは複数指定可。点数は画面から外した（2026-10-03。保存済みの値は残す）。一覧で 2 件を選び（◯を押した順に ①基準・②比較、⇄ で入れ替え）、比較画面へ進む。1 本を開くと、動画を再生（止めているときだけ角度表）、タイトル・メモなどの編集、撃発ポイントの修正、切り抜き範囲の修正、削除
7. 比較：①基準と②比較の 2 本を重ね描き（第 7 章）。差分表（既定は非表示、ボタンで表示）。角度時系列グラフは初期バージョンでは作らない（第 14 章）
8. 静止ノイズ測定モード（第 8 章。開発用。URL に `?noise=1` を付けたときだけ入口を出す）
9. 書き出し・読込：JSON（全データ）、CSV（角度時系列）、PNG（重ね描き画像）。JSON は読込可能で端末間共有に使う
10. 射手の登録（名前と利き手〔右／左〕）。利き手は射手ごとに 1 回決め、動画のたびには選ばない。同じ名前の射手は 1 人まで。内部は「銃側／非銃側」で扱い、表示の意味が同じになるよう左利きは反転
11. 保存はブラウザ内データベース（IndexedDB）。初回画面で「ホーム画面に追加」と「JSON 書き出し」を促す（iOS Safari は 7 日間未使用のサイトの保存データを消すことがあり、ホーム画面追加で回避できる）

## 6. 計測定義

### 6.1 使用する点（MediaPipe の 33 点から）

| 名称 | 定義 |
|---|---|
| 銃側手首 | 利き手側の wrist |
| 両肩 | left/right shoulder |
| 肩中心 | 両肩の中点 |
| 両腰 | left/right hip（大転子付近に出る点。実際の骨盤中心より外側・下方に出ることを承知のうえで使用） |
| 腰中心 | 両腰の中点 |
| 顔 | 銃側の耳（右射手をへそ側から撮ると、頭はターゲット方向＝画面左を向くため、カメラに見えるのは銃側の耳）。visibility が低ければ鼻に代替 |
| 両足首 | left/right ankle |

visibility（MediaPipe が出す「その点がどれだけ見えているか」の値）が閾値未満の点は計測から外し、グレー表示、角度は「—」とする。画面の外にある点も、visibility が高くても同じく計測から外す（足首が切れた動画などで、モデルが画面外の関節の位置を推測して高い visibility を付けることがあるため）。

### 6.2 角度・距離の一覧

| 記号 | 名称 | 定義 | 基準 |
|---|---|---|---|
| (a) | 肩線の傾き | 両肩を結ぶ線 | 水平 |
| (b) | 腰線の傾き | 両腰を結ぶ線 | 水平 |
| (c) | 体軸の傾き | 腰中心 → 肩中心 | 鉛直 |
| (d) | 首の傾き | 肩中心 → 顔 | 鉛直 |
| (f) | 腕の挙上角 | 銃側肩 → 銃側手首 | 水平 |
| (g) | 腕と肩線のなす角 | (f) の線と (a) の線 | 身体基準 |
| (h) | 腰中心の横ずれ | 両足首中点に対する腰中心の水平オフセット | 体幹長で正規化した比率 |
| (i) | スタンス幅 | 両足首間距離 ÷ 体幹長 | 比率 |
| (j) | 手首と顔の水平距離 | 銃側手首と顔の x 座標差 ÷ 体幹長 | 比率 |

(e) 頭の傾きは計測不能のため除外。

### 6.3 基準と符号

- 基準は「カメラの水平・鉛直」と「身体基準」の両方を持つ
- 水平校正（カメラの傾きの補正）は **初期バージョンから外した**（2026-10-03、開発者の決定。利用者が必要と感じないため）。水平・鉛直基準の角度は、カメラの向きをそのまま基準にする
  - 段階④でいったん実装した（静止画に水平または鉛直の線を引いて補正する）。engine の計算（`normalize/level.ts`）と保存形式の項目（`level`）は残してあり、画面からは使わない。以前に引いた線が保存されていても、角度の計算には使わない
  - 分かっていた限界：カメラが上や下を向いていると、鉛直なものは画面の端に近いほど斜めに写る（ユーザー候補の動画では 100 画素につき 0.6〜1.0°）ため、線 1 本では 1〜2° ずれる
- 符号：銃側へ傾く・上がる＝正。左利きは内部で反転

### 6.4 正規化（重ね描き用）

- 既定：腰中心で平行移動、体幹長（腰中心 → 肩中心）でスケール
- トグルで生の画素座標のまま重ねることも可能（立ち位置のずれ自体を見たいとき）

## 7. 比較の定義

- (a) 2 本の動画を重ね、撃発ポイントを 0 とした **1 本のバー**で 2 本を一緒に動かして比べる（2026-10-03、段階⑤で「基準用と比較用の 2 本のバー」から変更）
  - バーの範囲は 2 本に共通する区間。撃発より前は 2 本の「前の長さ」の短い方、後は「後の長さ」の短い方に合わせる（時間の伸縮はしない）。長い方の動画はその分だけ切り詰めて扱う
  - ②比較の動画の上に、①基準の動画を半透明で重ねる（濃さは調整可）。絵を押している間は基準だけを表示し、離すと比較に戻る
  - 位置合わせ（腰の中心と体幹の長さを揃える）は撃発の瞬間の姿勢で決め、時点を動かしても合わせ直さない（体の動きを打ち消さないため）
  - 再生：◀1 コマ／▶ 再生／1 コマ▶、速さ 1 倍・1/2・1/4、繰り返し（共通の区間の全体を回る）。再生中は 2 本のずれを監視し、1 コマ以上ずれたら合わせ直す
  - 音のグラフは 2 本分を色分けして重ねる（山が重なっていれば撃発ポイントが合っている）
  - 撃発ポイントの修正は、比較画面では重ねたまま行う（2026-10-04、開発者の希望。2 本の撃発ポイントがずれているとき、相手を見ながら揃えるため）：動かす側（①基準／②比較）を選び、「1 コマ早く／遅く」で 1 コマずつ動かすか、「音の山に合わせる」（その動画の撃発ポイントの前後 1 秒・切り抜きの範囲内で、音が最大の時点にいちばん近いコマへ移す）で揃える。修正中はバーを撃発の前後 1 秒に拡大し、動かした量を数字で出す。「決定」で保存（撃発の瞬間の静止画も作り直す）、「キャンセル」で元に戻る。①②の両方を動かしてまとめて決定できる
  - 切り抜き範囲の修正も、比較画面では重ねたまま行う：撃発を 0 とした開始・終了を 1 組決め、①②の両方の動画に当てはめる（2026-10-03、開発者の希望）。直すと共通の区間が計算し直される
  - 差分表は、選んだ時点どうしの差を出す
- 角度の数値（動画を再生の角度表、比較画面の差分表）は、**既定では非表示**にし、ボタンを押したときだけ出す（2026-10-03、開発者の決定。絵の比較が主で、数値の必要性は薄いため）。開閉の状態は端末に覚えておき、全画面で共通にする。「動画を再生」の角度表は、止めているときだけ出す
- (b) 角度時系列グラフは初期バージョンでは作らない（2026-10-03。将来候補、第 14 章）
- 同期点は撃発ポイント（1 動画に 1 つ）。任意マークによる同期は初期バージョンでは行わない
- 差分表示：基準値・比較値・差分の 3 列表。差分＝比較 − 基準。表の数字どうしの引き算が合うよう、表示の桁（角度 0.1°、比 0.01）に丸めてから差を取る
- 色分け：差がノイズ幅（第 8 章）の 2 倍以上で黄、3 倍以上で赤。色だけに頼らないよう ◇・◆ の印も付ける。差は 2 つの測定値の引き算で揺れが約 1.4 倍になるため、1 倍では姿勢が同じでも約半分の項目に色が付いてしまう。閾値はユーザーが上書き可（設定画面と一緒に実装する）
- 重ね描き：基準は半透明の別色（桃色の点線）。横並び表示もトグルで可
- 利き手が違う 2 件は、位置と大きさを揃えるときに基準を左右反転して重ねる。肩や腰が見えず揃えられない 2 件は「撮ったまま」で重ね、画面の縦横比も違えば重ねず、差分表（ボタンで表示）だけで比べる

## 8. 静止ノイズ測定

- 三脚固定・射手が静止した動画を読み込み、各角度のノイズ幅（標準偏差）を表示するモード
- 得られた値を差分表示の色分け閾値の既定値に流用
- 開発上の意味：MediaPipe の点は静止していても数ピクセル揺れる。1080p の全身像では肩線の角度で ±1° 前後のノイズが見込まれる（推定、要実測）。友人が見たい差がこれより小さければ、複数フレーム平均や高解像度化を先に検討する

## 9. データ仕様

- 保存単位：処理済み動画 1 件。保存形式は版番号を持つ（版 2：水平校正の線の項目を追加〔初期バージョンでは使わない〕。版 3：切り抜きの範囲とタイトルを追加〔2026-10-03〕。古い版の記録は、線なし・範囲は全体・タイトルは撮影日時として自動で移し替える）
- ライブラリで選んだ 2 件（①基準・②比較）は、端末ごとの設定として覚えておく
- 保存項目：動画本体、ランドマーク時系列（共通ランドマーク形式の 11 点 × x, y, visibility × フレーム。切り抜きの範囲の外も含めて全長）、fps・解像度・元の動画の長さ、撃発ポイント（マーク。任意ラベルのマークも形式には残す）、切り抜きの範囲（開始・終了の時刻。全体なら「なし」。撃発ポイントを含むこと）、水平校正の線、メタ情報（タイトル〔60 字まで〕、撮影日時、射手、点数〔画面から外した。保存済みの値は残す〕、メモ〔100 字まで〕、お気に入り）、使用した姿勢推定モデルの名前（例：`mediapipe-full-video`）、静止画（撃発フレーム 1 枚と、一覧用に人物を切り抜いた小さい 1 枚）
- 音の大きさのグラフは保存せず、開くたびに動画本体から計算する（音声を取り出し、短い区切りごとの最大振幅を並べる。1 分の動画で 1 秒かからない）
- 射手：名前と利き手を記録とは別に持ち、記録は射手を参照する。射手の名前や利き手を直すと、その射手の記録すべてに反映される。記録の射手は保存後も替えられる
- 撮影日時：端末の現地時刻で持つ（時差の情報は持たない）。初期値は動画ファイルの更新日時で、後から編集できる
- 角度時系列は保存しない。開くたびにランドマークと射手の利き手から計算する（二重に持つと食い違いの原因になるため。JSON・CSV の書き出しには含める）
- 動画本体は、記録と一緒に端末内に保存する（2026-10-02 変更。それまでは「保存しない」）。射撃はスタンバイ姿勢から撃発後のフォロースルーまでの全体とそのつながりが重要で、比較画面で任意の時点の絵どうしを重ねるため
  - 選んだ動画ファイルをそのまま保存する（変換しない）。1 件あたりの容量は動画ファイルの大きさと同じ（30 秒で 30〜50 MB 程度）
  - 端末の空き容量が足りず動画を保存できなかったときは、記録だけを保存し、その旨を知らせる
  - 動画のない記録（変更前に保存した記録など）には、記録を作ったときと同じ動画ファイルを選んで、あとから付けられる（画面の大きさと長さが同じことを確かめる）
  - ライブラリに、端末で使っている保存容量を表示する
- JSON：上記すべて。読込可
- CSV：角度時系列（列名は第 6.2 章の名称）
- PNG：重ね描き画像

## 10. 画面構成と操作フロー

入口は「動画の保存」「ライブラリ」の 2 つ（2026-10-03、段階⑤で 5 タブから変更）。入口のタブは青を使わない（青は「次に押すボタン」専用）。

1. 動画の保存（5 段階。2026-10-04 に 4 段階から変更。上に進み具合の帯〔1 射手・2 動画・3 切り抜き・4 撃発・5 保存〕を出し、帯の下に今の段階の正式な名前を出す。画面の文言に「手順 1：」のような番号は付けない）
   1. 射手の選択：前回の射手が選択済み。登録・編集もここで行う。「次へ（動画を選ぶ）」で進む。射手は利き手（角度の符号）に関わるので、動画を選ぶ前に決める
   2. 動画の指定：上に選んだ射手を出す（「射手を選び直す」で戻れる。読み込んだ動画は消えない）。「ファイルを選択」ボタンの右に「ファイル未選択」、読み込んだあとは「選択済み」と選び直しの案内（ブラウザ本来のファイル選択欄は出さない）。選んだ直後、動画の読み込みとフレームレートの推定が終わるまでは「しばらくお待ちください」だけをゆっくり点滅させて出す。「姿勢推定を実行」（進捗・中断）。推定が終わると、自動で切り抜きへ進む
   3. 切り抜き：動画と骨格、音のグラフ、開始・終了の取っ手と「ここを開始に／ここを終了に」。時点のつまみは丸。「範囲を確定 → 撃発ポイントの特定へ」。「戻る」は動画の指定へ戻る（保存していない動画があることを確認する）
   4. 撃発ポイントの特定：切り抜いた範囲だけを動かす。つまみは先の尖った ▲ と縦線で、音の山に目で合わせられる。音の最大に当たりを付けてあり、修正が必要なときだけ指定し直す。「撃発ポイントを確定」を押すと、自動で保存へ進む
   5. 保存：タイトル（初期値は撮影日時）・射手・撮影日時・メモ・お気に入り。保存後は「次の動画を保存する」（射手の選択へ戻る）「ライブラリで見る」
   - 骨格の色の説明（緑・灰の凡例）は画面に出さない（2026-10-04）
2. ライブラリ：一覧（射手名フィルタ、お気に入りのみのフィルタ、お気に入りの切替）、右の◯で 2 件を選び「この 2 件を比較する」。タイトルを押すと詳細
   - 詳細：静止画＋骨格、タイトル・射手・撮影日時・長さ（元の長さと範囲）・撃発・メモ、「動画を再生（角度などの情報を表示）」「タイトル・メモなどを編集」「撃発ポイントの修正」「切り抜き範囲の修正」「この動画を削除」
   - 動画を再生：1 本のプレイヤー（バー・音のグラフ・◀1 コマ／▶ 再生／1 コマ▶・速さ・繰り返し）。止めているときはそのコマの角度表。撃発ポイントの修正・切り抜き範囲の修正は同じ画面で、下のボタンが変わる
3. 比較：ライブラリから入る。重ね描き／横並び、基準の濃さ、1 本のバー（0 ＝ 撃発）、再生・速さ・繰り返し、位置合わせの切替、撃発ポイントの修正・切り抜き範囲の修正（どちらも重ねたまま）、角度情報の表示（差分表、ボタンで表示）。「← ライブラリへ」で戻る
4. 設定画面：平滑化、閾値（未実装。利き手は射手の登録で決める）
5. 静止ノイズ測定画面（開発用、`?noise=1`）

## 11. 技術構成

| 部品 | 採用 | 説明 |
|---|---|---|
| 画面の組み立て | React | 画面部品を組み立てる仕組み |
| プログラム言語 | TypeScript | JavaScript に型を足した言語。誤りを実行前に見つけられる |
| まとめ道具 | Vite | プログラムをブラウザで動く形に束ねる道具。出力をそのまま公開 |
| 姿勢推定 | MediaPipe Tasks Vision（ブラウザ版） | 関節 33 点を検出。モデルは full・動画モードに固定（利用者には選ばせない） |
| グラフ | Chart.js | 角度時系列の折れ線 |
| 保存 | Dexie | ブラウザ内データベース IndexedDB の扱いを簡単にする部品 |

- すべて無料・オープンソース。MediaPipe は Apache 2.0 で、MIT のアプリに組み込んで問題なし
- 姿勢推定と角度計算は画面から切り離した独立部品（ライブラリ）として作り、将来別アプリに組み込めるようにする
- 姿勢推定の出力はモデルごとに異なる（MediaPipe 33 点、MoveNet・RTMPose・ViTPose は COCO 形式 17 点、Sapiens 2 は 308 点）。engine の内側に「共通ランドマーク形式」（6.1 章の点：鼻・両耳・両肩・両腰・両手首・両足首、各 x, y, visibility）を定義し、どのモデルの出力もそこへ変換してから角度計算に回す。角度計算・比較画面はモデルに依存しない
- 姿勢推定バックエンドは差し替え可能にする。ブラウザ内は MediaPipe を使う。段階①で MoveNet Thunder（Google、TensorFlow.js）、MediaPipe lite／heavy と同じ動画で静止ノイズを比較済み。すべて合格ライン内だったため、MediaPipe full に一本化した
- 文言は最初から分離しておき、英語化を容易にする（v1 は日本語のみ）

## 12. 開発順序と検収基準

| 段階 | 内容 | 合格ライン |
|---|---|---|
| ① | 動画読込 → 姿勢推定 → 骨格重ね描き → 静止ノイズ測定 | iPhone の Safari で、処理時間が動画の長さの 6 倍以内。静止ノイズは肩線・体軸の SD（標準偏差）が 1° 以内 |
| ② | マーク付け → 撃発フレームの角度表 | — |
| ③ | ライブラリ、射手名、お気に入り | — |
| ④ | 2 動画の重ね描き＋差分表、正規化トグル（水平校正は初期バージョンから外した） | 同一射手の別日動画を正規化して重ねたとき骨格がおおむね一致する |
| ⑤ | 入口を 2 つに、切り抜き、撃発ポイント（音のグラフと自動の当たり）、ライブラリでの 2 件選択と修正、1 本のバーと再生・速さ・繰り返しの比較（2026-10-03 に内容を見直し。角度時系列グラフは作らない） | 自動の当たりが、ユーザー候補の動画で実際の撃発から 3 コマ以内に入る |
| ⑥ | JSON／CSV／PNG 書き出しと JSON 読込 | — |
| ⑦ | PWA 化、文言分離 | — |
| ⑧（条件付き） | Mac 用 Python 変換ツール（高精度モード）。動画を入れると共通ランドマーク形式の JSON を出し、Web アプリの JSON 読込で取り込む。まず RTMPose、Apple Silicon 機に更新後 Sapiens 2／ViTPose を追加検討 | ①のノイズ幅が合格ラインに届かない場合にのみ着手 |

- ①で速度が出なければ、モデル・解像度の方針を見直す
- 友人の動画でノイズが合格ラインに届かなければ⑧へ進む。この場合、高精度処理はつよしの Mac で行い JSON を渡す運用を基本とし、その部分は端末内完結の例外とする（友人の動画を預かる前提）
- まず自分の動画で作り込み、ある程度できてから友人に触ってもらう
- 検証動画：友人から最低 3 本（好調時 1 本、不調時 2 本）を入手。可能なら Android 撮影のものも
- 期限なし
