## 4. 実装の要点（コードを読む前に知っておくこと）

### 構成

```
packages/engine/src/
  landmarks/   共通ランドマーク形式、fromMediaPipe、fromCoco17（現在未使用。⑧用に残置）
  normalize/   利き手反転（toSided、mirrorX）
  metrics/     角度・距離 (a)〜(j) の計算
  noise/       要約統計（平均・SD）
  pose/        PoseBackend、MediaPipeBackend、Web Worker、PoseWorkerClient
apps/web/src/
  screens/     LoadScreen（画面 1）、NoiseScreen（画面 2）
  components/  VideoPlayer、SkeletonOverlay、DevErrorBanner（開発サーバ限定）
  analysis/    runAnalysis（全フレーム処理）、frames（フレーム番号）、metrics
  video/       load（動画読込）、seek（シーク・fps 推定）
  config/      backends（モデル設定は 1 種類に固定）
  dev/         AutoTest（開発サーバ限定の自動テストモード）
  i18n/ja.ts   画面の文言
apps/web/e2e/
  autotest.mjs        Playwright で自動テストを実行
  devReportPlugin.ts  開発サーバ限定の Vite プラグイン（/t、/_test/、結果の受け取り）
  videos/             テスト動画（git 管理外）
  results/            テスト結果（git 管理外）
```

### 座標と符号の取り決め

- 座標は画素単位、y は下向きが正
- 利き手の正規化後は「右利きの見え方」に統一。カメラはへそ側にあるため、**銃側（右半身）は画面の左**に写る。実際の動画で確認済み
- 符号：銃側へ傾く・上がる＝正

### フレームの取り出し（はまりやすい点）

- HTML video は fps を教えてくれない。先頭 1 秒を 1/120 秒刻みでシークし、フレームが切り替わった時刻の**間隔の中央値**から推定する（静止した映像で切り替わりを見落としても狂わないため）
- 解析もコマ送りも、各フレームの**真ん中の時刻**へシークする（境界ぴったりだと前後どちらが出るか曖昧）
- `requestVideoFrameCallback`（表示されたフレームの時刻を教える機能）は、動画が画面に表示されていないと呼ばれない。呼ばれない場合は上の「真ん中へシーク」だけで進む
- 表示中フレームの判定は「その時刻を含むフレーム」（`frameIndexAt`）
- video 要素は React の state ではなく ref で持つ（React Compiler の静的検査が state の直接変更を禁じるため）

### ビルドまわり

- MediaPipe の wasm は `?url` で Vite に配置させる（`public/` に置くと開発サーバが JavaScript として読み込めない）。パッケージの公開名は `@mediapipe/tasks-vision/vision_wasm_module_internal.js`（`wasm/` を付けない）
- 開発サーバは `server.host: true` で常に同じ Wi-Fi に公開
- TypeScript は 5.9（7 系は typescript-eslint が未対応）、React は 18

## 5. 自動テストの使い方

開発サーバを起動した状態で実行する（Claude は `preview_start` の `web` で起動。`.claude/launch.json` に定義済み）。

```
node apps/web/e2e/autotest.mjs webkit   video=/_test/static.mp4 repeat=2
node apps/web/e2e/autotest.mjs chromium video=/_test/sample.mov start=4.7 end=8.5
```

- テスト動画：`apps/web/e2e/videos/sample.mov`（開発者提供の 31 秒）、`static.mp4`（据銃区間 4.7〜8.5 秒の切り出し）。git 管理外なので、無ければ `~/Downloads/IMG_6857.mov` からコピーし、`ffmpeg -ss 4.7 -to 8.5 -i sample.mov -c:v libx264 -crf 16 -pix_fmt yuv420p -an static.mp4` で作り直す
- 画面を実際に表示して動かす（`headless: false`）。非表示だと挙動が実機と変わる
- iPhone 実機：開発者に Safari で `192.168.1.6:5173/t` を開いてもらう（IP は `ipconfig getifaddr en0` で確認）。結果は `apps/web/e2e/results/device-*.json` に届く
- Claude の内蔵ブラウザはページが非表示扱いになり、速度の数値は当てにならない。流れの確認にだけ使う
- この Mac には Xcode がなく、iOS シミュレータは使えない

**画面や解析に手を入れたら、コミット前に WebKit と Chrome の両方で自動テストを回すこと。**
