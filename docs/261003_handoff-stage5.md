## 4. 実装の要点（はまった点）

### 動画（WebKit）

- **動画を IndexedDB に Blob（File）のまま入れると、WebKit で保存に失敗する。** バイト列（ArrayBuffer）で `recordVideos` 表に入れ、
  表示のときに Blob と一時 URL を作り直す（`components/useRecordVideoUrl.ts`）
- **loadedmetadata の時点で時刻を移すと、絵が黒いままになる。** loadeddata で移す（`components/CompareStage.tsx`）
- video の URL は effect で 1 回だけ渡して `load()` する。属性で渡してから `load()` すると読み込みが 2 回始まる
- video 要素は、置いたら動かさない。重ねる↔横に並べるの切替では作り直されるので、先に止めて時点を保つ
- バーを引いている間は、前のシークが終わってから最新の時刻へ 1 回だけ移す
- WebKit の自動テストで「WebKitBlobResource error 1」が 20〜30 件出る。画面を離れて URL を解放したあとも
  ブラウザが読み込みを続けようとするため。動作には影響しない

### 比較画面の構成

- `screens/CompareScreen.tsx`：2 件の選択と案内。`screens/CompareView.tsx`：図・バー・再生・差分表
- `components/CompareStage.tsx`：video を CSS の matrix で拡大・移動し、その上に SVG（骨格）を重ねる
- `compare/layout.ts`：重ね方と表示範囲の計算（単体テスト付き）。表示範囲は動画全体を通した人物の範囲（`sequenceBounds`）
- 連動は、入れた瞬間の時刻差を保つ。相手の時点は「いちばん近いフレーム」で選ぶ（境目の丸めで 1 コマずれるため）
- 絵を押して基準に切り替える操作は、押してから 0.18 秒待ち、指が 10px 以上動いたら取り消す（スクロールと区別）

### 角度の数値の表示切替

- `components/NumbersFold.tsx`（見出しを兼ねた開閉ボタン）と `components/useShowNumbers.ts`
  （`localStorage` の `kamae.showNumbers`）。自動テストは `addInitScript` で最初から「表示」にしている

### データベース

- Dexie の版 3。版 2 で記録を保存形式の版 2（`level` 項目）に移し替え、版 3 で `recordVideos` 表を追加
- 開発サーバは Claude のセッションに紐づき、セッションが切り替わると止まる。
  **開発者に実機確認を頼む直前に、必ず `http://192.168.1.6:5173/` が 200 を返すことを確かめる**

## 7. 未了の事項・将来の候補

- **メモリ**：保存と表示のとき、動画全体を一度メモリに載せる。100 MB 級の動画を 2 本重ねると iPhone でブラウザが
  落ちる恐れがある（開発者の確認では問題は出ていない）。根本対策は OPFS（ブラウザ内の専用ファイル置き場）に書いて、
  メモリに載せずに再生すること
- **データが消える恐れ**：iPhone の Safari は、ホーム画面に追加していないサイトの保存データを、7 日間使わないと
  消すことがある。動画も対象。段階⑦（ホーム画面への追加）で対処する
- 動画だけを外して容量を空ける機能（今は記録ごと削除する）
- あと付けの照合を確実にする（ファイルの大きさ・名前を記録に持たせる。保存形式の変更になる）
- 書き出し（⑥）で動画をどう扱うか（JSON には含めない想定）
- 色分けの閾値を利用者が変える機能（設定画面と一緒に）
- 「撮ったまま」で利き手が違う 2 件を重ねたときの案内
- 段階③までの候補：可変フレームレート、撮影の案内、射手の削除、タブの下固定
