## 3. 段階④で決めたこと

### 開発者の決定（2026-10-01）

| 項目 | 決定 |
|---|---|
| 比べる相手 | 基準（お気に入りから選ぶ）とライブラリの任意の 1 件。読み込み中の動画は保存してから比べる |
| 水平の線を引く場所 | ライブラリで開いた記録の静止画の上、1 か所だけ（マーク画面にはない） |
| 差の色分け | 測定の揺れの 2 倍以上で黄（◇）、3 倍以上で赤（◆）。揺れの幅は角度 0.3°（(g) は 0.4°）、比 0.01 |
| 鉛直の線 | 水平なものだけでなく、鉛直なもの（柱・ドア枠）に合わせた線でも補正できる（承認済み） |
| UI の検討 | 複数エージェントの相互批評は不要。開発者に確認を求める前に、別エージェントに 1 回レビューさせる |

### Claude が決めて報告したこと（技術的な選択）

| 項目 | 決定 | 理由 |
|---|---|---|
| 差の計算 | 表示の桁（角度 0.1°、比 0.01）に丸めてから引く | 表の数字どうしの引き算が合うようにする（12.4 と 13.1 の差が 0.6 と出ない） |
| 水平校正の適用 | 角度を計算する直前に、関節の位置を画像の中心まわりに回す（`applyLevel`）。画面の外の点は回す前に外す | 保存データは変えず、線を消せば元に戻る |
| 重ね描きの座標 | 「今回」の写真の座標に基準の骨格を移す。写真は回さず、基準を「傾きの差」の分だけ回す | 写真と骨格がずれない |
| 揃え方 | 腰の中心を重ね、体幹の長さを合わせる。利き手が違えば基準を左右反転（揃えるときだけ） | 要件 6.4 |
| 撮ったまま | 縦横比が同じときだけ。画素数が違えば幅を合わせる拡大縮小のみ | 縦横比が違う 2 件は意味がない |
| 揃えられず縦横比も違う | 基準の骨格を重ねず、理由の帯と差分表だけ | 矛盾した図を出さない |
| 線の検査 | 長い辺の 20% 未満の線と、10° を超える傾きの線は決められない。記録の検査は形だけ | 奥へ延びる線の誤用を防ぐ。閾値を変えても古い記録が開けなくなることがない |
| 線の端の操作 | 端より 36px 下のつまみ（直径 44px）を引きずる。拡大鏡（4 倍）と矢印キー（1 画素、Shift で 10 画素） | 指で端が隠れない |
| 記録の見出し部品 | `RecordSummary` を一覧と選ぶ窓で共用 | 見た目を揃える |
| 比べる 2 件の記憶 | `settings` 表に保存。削除された記録は開くときに外す | 次に開いたときも同じ 2 件 |

## 4. 実装の要点

- engine：`normalize/affine.ts`（点の移し替え）、`normalize/level.ts`（水平校正）、`normalize/align.ts`（正規化）、
  `metrics/diff.ts`（差と色分け）。`metricsAtFrame` に `tiltDeg`。`record/validate.ts` に `upgradeShotRecord`・
  `tiltDegOfRecord`・`hasUsableLevel`
- web：`compare/layout.ts`（重ね方と表示範囲の計算、単体テスト付き）、`components/LevelEditor.tsx`（線を引く窓）、
  `components/DiffTable.tsx`、`components/RecordPicker.tsx`、`components/SkeletonLayer.tsx`（骨格の描画を共通化）、
  `screens/CompareScreen.tsx`
- `StillView` に `baseParts`（基準の骨格）と `variant` を足した。骨格の色は `components/skeleton.ts` と
  `styles.css` の `--skel-*` の 2 か所にある（見本の線のため）
- 線を引く窓は SVG 全体を `touch-action: none` にしている（つまみだけにすると iOS で効かない恐れがあるため）。
  写真の上では画面をスクロールできない。iPhone で「つまみを動かしている間に画面が動かない」ことを要確認
- 「基準と比べる」で来たときだけ、基準が未選択なら選ぶ窓を自動で開く（App の `autoPickBase`、1 回で消える）

### 分かったこと：遠近による鉛直の線のずれ

ユーザー候補の動画 6 本で、静止画の中の鉛直なもの（鏡の枠、壁の継ぎ目、机の脚）の写り方を調べたところ、
**画面の右へ行くほど時計回りに傾いて写る**（100 画素につき 0.6〜1.0°）。カメラが少し下を向いているためで、
6 本とも同じ傾向。射手のすぐ右の鏡の枠（射手から 200 画素ほど右）に線を引くと、射手の位置での鉛直より
1.2〜2.0° 大きい傾きになる。6 本の間の違いとしては最大 0.8°（bad-3 と good-1）で、黄の境目（0.6°）に届く。

射手の位置での鉛直を、左右 2 本の鉛直な線から補間して求めれば解ける（engine は小さい変更。画面は
2 本目の線をオプションで足す形）。水平な線も、カメラが壁に正対していないと上下の位置で傾きが変わるので、
同じ問題がある。今の実装では、線を引く画面に「射手のすぐ近くの線を選ぶ」案内と、離れた鉛直の線への注意を
出している。

## 8. 仕様変更（2026-10-02、開発者の指示）

開発者が iPhone で確認し、「撃発の瞬間の静止画でしか比べられない」「基準は骨格しか出ない」のは求める機能として
不足、と判断した。射撃はスタンバイ姿勢から撃発後のフォロースルーまでの全体とそのつながりが重要なため。

### 決定

| 項目 | 決定 |
|---|---|
| 動画本体 | **端末内に保存する**（CLAUDE.md 2 章の絶対条件と要件 9 章を書き換えた）。選んだファイルをそのまま、変換せずに保存 |
| 時点 | 基準と今回に別々のバー。任意の時点どうしを比べる。開いた直後は、どちらも撃発の瞬間 |
| 重ね方 | 今回の動画の上に基準の動画を半透明で重ねる（濃さのつまみ）。絵を押している間は基準だけ |
| 連動 | 「2 本を一緒に動かす」スイッチ（片方を動かした秒数だけ、もう片方も動く）。2 本の同時再生も付けた |
| 鉛直線 2 本 | 仕様変更のあとに、「吸着」（おおまかに引いた線を近くの縁に合わせ直す）と合わせて試作し、数値を見て採否を決める |

### 実装の要点

- 動画は `recordVideos` 表にバイト列で保存する。**Blob（File）のままだと WebKit で保存に失敗する**（実測）。
  記録とは別に保存し、失敗しても記録は残る（保存後の帯に案内）
- 動画のない記録（変更前の記録、保存に失敗した記録）には、`AttachVideo`（比較画面の案内と、開いた記録）から
  同じ動画ファイルを選んで付けられる。画面の大きさと長さ（±0.05 秒）が同じことを確かめる
- 比較の図は `components/CompareStage.tsx`。video 要素を CSS の matrix で拡大・移動し、その上に SVG（骨格）を重ねる。
  **WebKit は、loadedmetadata の時点で時刻を移すと絵が黒いままになる。loadeddata で移す**（自動テストの絵の検査で発見）
- 位置合わせ（揃える）は撃発の瞬間の姿勢で決め、時点を動かしても合わせ直さない。表示範囲は動画全体を通した
  人物の範囲（`sequenceBounds`）から決める
- 比較画面の本体は `screens/CompareView.tsx`、2 件の選択と案内は `CompareScreen.tsx`
- WebKit の自動テストで「WebKitBlobResource error 1」が 20〜30 件出る。画面を離れて動画の URL を解放したあとも、
  ブラウザが読み込みを続けようとするため。動作には影響しない
- 実測（Mac、動画 2 本・計 70 MB）：保存 0.5 秒、読み出し 0.15 秒、2 本同時の時点移動は WebKit 36 ミリ秒・
  Chrome 120 ミリ秒
